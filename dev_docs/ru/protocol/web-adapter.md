# Руководство по адаптеру UART↔Web

## Цель
Связать бинарный TLV-протокол RP2040 (`PROTOCOL.md`) с JSON‑API портала поверх Socket.IO (`DRYER_DEVICE_API.md`). ESP принимает UART, переводит кадры и публикует их в WebSocket без ручной обработки каждого пункта меню.

## Источники данных
- **Схема меню**: используйте `src/menu/menu_v2.yaml` (или сгенерированные заголовки), чтобы на этапе сборки ESP собрать таблицу `{ menuId -> { name, type, unit } }`. Сохраните её во flash как `menu_map.json`.
- **Ключи телеметрии**: отзеркальте `telemetry_keys.h` в JSON-справочник с именами и единицами.

## Поток UART → JSON
1. Парсим TLV-кадр в `{ msgType, msgId, tlv[] }`. Отклоняем неверный CRC, версию и неизвестные типы TLV.
2. Подставляем значения через lookup-таблицы:
   - `MENU_ID` → `menu.name`, `menu.type`.
   - `VALUE` → приводим к float/int/bool исходя из метаданных.
   - `CTRL_INDEX`, `UNIT_ID` и т. п. копируем как числа.
3. Формируем нормализованный JSON:
   ```json
   {
     "type": "SET_VALUE",
     "menuId": "0003",
     "menuName": "dryTemp",
     "ctrlIndex": 0,
     "value": 55.0,
     "raw": "AA0102..."
   }
   ```
4. Отправляем через Socket.IO:
   - События меню → `telemetry:data` c `data.menu[menuName]`.
   - Телеметрические TLV → разворачиваем в поля DTO согласно каталогу.
   - ACK/ERROR → транслируем в `command:result` обратно в портал.

## Поток JSON → UART
1. Принимаем команду портала (например, `command:execute`, `{ "menu": "dryTemp", "value": 55 }`).
2. Находим метаданные меню, чтобы получить `menuId`, тип и область контроллера.
3. Собираем TLV-кадр (`SET_VALUE` или `INVOKE_ACTION`), прикручиваем CRC16 и пишем в UART.
4. Ведём `msgId`, чтобы сопоставить ответы (`ACK`/`ERROR`) и отправить подтверждение порталу.

## Ошибки и логи
- Храним последние N raw-кадров для диагностики (`logs/uart.log`). Добавляем поле `raw` в каждый JSON.
- Если меню/ключ неизвестен, отдаём `command:result` c `status: "unsupported"` и не пишем в UART.
- Для восстановления после десинхронизации запросите `SYNC_SNAPSHOT` и обновите кеш состояния.

Такой адаптер изолирует прошивку RP2040 от изменений портала: облако остаётся JSON-ориентированным, а на проводе по‑прежнему идёт компактный TLV.
